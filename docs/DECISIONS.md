# Discord Chat Extractor — 제품/기술 판단 목록

> **For English readers:** this is a list (in Korean, numbered 1–42) of the product and technical decisions made during design where the original brief was silent: A. architecture and tech, B. data loading, C. selection and download UX, D. export formats, E. UI, F. security, risks and what was verified. Some entries also say what was deliberately left out. The architecture and contracts are in English in [ARCHITECTURE.md](ARCHITECTURE.md); how to use the app is in [USAGE.en.md](USAGE.en.md).

설계하면서 처음 요구사항에 정해져 있지 않았던 부분을 어떻게 정했는지 모은 목록입니다.
(처음부터 정해져 있던 요구사항: 크롬 확장 + Discord와 동일한 UI의 웹앱, 로그인된 크롬 세션 사용, 서버/DM/채널 선택 후 우상단 다운로드, 첫 렌더는 이름·아이콘 등 최소 정보만,
채널 선택 시 200개 → 위로 스크롤하면 200개씩 추가, 프로필·고정메시지·멤버 등 불필요 기능 제외.)

## A. 구조 · 기술
1. **스택**: Manifest V3 + Vite + TypeScript(strict) + React 19 + Zustand + fflate(ZIP). 테스트는 Vitest. 런타임 의존성은 4개뿐(react, react-dom, zustand, fflate).
2. **프로젝트 이름**: 영문명 *Discord Chat Extractor* (저장소명 `discord-chat-extractor`).
3. **웹앱 형태**: 툴바 아이콘 클릭 → 확장 프로그램 페이지(`app.html`)가 새 탭으로 열림. 이미 열려 있으면 그 탭으로 포커스(중복 탭 방지).
4. **로그인 정보(토큰) 획득**: 이미 열려 있는 Discord 웹 클라이언트(discord.com / ptb / canary)가 보내는 API 요청의 `Authorization` 헤더를 백그라운드 워커가
   **읽기 전용으로 관찰**(`chrome.webRequest`). content script·DOM/웹팩 해킹·쿠키 접근 없음. `Bearer`/`Bot` 토큰과 다른 서브도메인(support 등)은 무시.
   토큰은 `chrome.storage.session`(디스크에 안 쓰이는 메모리 저장소)에만 보관, 브라우저 종료 시 사라짐.
5. **토큰이 아직 없을 때**(확장 설치 후 이미 열려 있던 Discord 탭 등): 안내 화면 + "Discord 탭 새로고침"/"Discord 열기" 버튼. 토큰이 잡히면 자동으로 이어짐.
6. **데모 모드** (`app.html?mock=1`, 확장 밖 개발 서버에서도 동작): 가짜 서버·채널·DM·수천 개의 메시지로 UI 전체를 Discord 없이 체험/테스트. 안내 화면에서 진입, 확장 안에서는 상단의 "데모 종료" 배지로 나옴.
7. **실시간(Gateway/WebSocket) 미사용**: 열람은 "스냅샷"입니다. 새 메시지 자동 갱신 없음(내보내기 용도에 불필요).
8. **외부 통신 최소화를 CSP로 강제**: 확장 페이지 CSP가 `default-src 'none'` + `connect-src 'self' https://discord.com` 이라 Discord API 외로는 요청을 보낼 수 없고(`npm run verify` 가 검사),
   이미지/영상은 Discord 도메인만 허용. 분석·원격 코드·외부 폰트 없음. 임베드 이미지는 Discord가 프록시한 URL만 사용.
9. **세션 중 토큰 변경**: 앱이 열려 있는 동안 다른 탭에서 새 토큰이 잡혀도 따라가지 않음(두 계정/두 Discord 버전을 동시에 쓸 때 앱이 계속 리셋되는 것을 방지).
   Discord가 401을 주면(만료) 안내 화면으로 돌아가고 캐시를 지움. 이때 방금 실패한 토큰과 같은 값일 때만 저장된 토큰을 지움.

## B. 데이터 로딩
10. **첫 렌더**: 요청 3번 — `users/@me`(계정 확인), 서버 목록(아이콘·이름), DM 목록(친구 아이콘·이름). 서버의 **카테고리·채널 이름은 서버를 처음 열거나 선택할 때** 가져와 메모리에 캐시
    (서버 수십 개를 시작 시 전부 조회하면 느리고 레이트리밋 위험이 커서). 이때 권한 계산용으로 역할/내 멤버 정보를 추가 조회(실패해도 무시). 메시지는 채널을 열기 전에는 절대 요청하지 않음.
11. **200개 = API 100개 요청 × 2회(순차)**. Discord API가 한 번에 최대 100개만 허용하기 때문. 위로 스크롤하면 같은 방식으로 200개씩 위에 추가(스크롤 위치 유지). 맨 위(채널 시작)에 닿으면 "채널의 시작" 배너를 표시하고 더 요청하지 않음.
12. **지원 채널**: 텍스트, 공지, 음성/스테이지 채널의 텍스트 채팅, 1:1 DM, 그룹 DM, **활성 포럼/미디어 게시글(스레드)**.
    - 라이브 모드의 스레드는 사용자 토큰에서 쓸 수 있는 엔드포인트 제약 때문에 **포럼/미디어 채널당 최대 100개(4페이지)까지만** 찾고, **일반 텍스트/공지 채널 아래의 스레드는 나열하지 못함**(데모 모드는 보여줌).
    - 제외: 보관된(archived) 스레드, 포럼/미디어 채널 자체(게시글만 선택 가능), 서버 디렉터리.
13. **접근 권한**: 역할·채널 권한 덮어쓰기로 볼 수 없다고 계산된 채널은 숨기지 않고 **자물쇠 + 선택 불가**로 표시(계산은 best-effort, 음성 채널은 CONNECT 권한도 필요).
    메시지 요청이 Discord 오류코드 50001/50013/50009 와 함께 403이면 자물쇠 처리, 그 외 403(Cloudflare/일시 차단 등)은 "일시적 오류 + 다시 시도"로 구분해 채널을 잠그지 않음.
14. **서버 순서**: API가 돌려주는 순서(Discord 앱의 사용자 정렬/폴더 설정은 API로 제공되지 않음). 서버 폴더 미지원.
15. **요청 방식**: 읽기(GET) 전용·순차 처리, `Retry-After`/`X-RateLimit-*` 준수, 지수 백오프. 요청 사이에 인위적 지연은 없음(백그라운드 탭에서 타이머가 1초 이상으로 늦춰지는 문제를 피하려고).
    Retry-After가 60초를 넘는 429(IP/Cloudflare 차단 유형)는 전역 대기로 처리하고, 내보내기 중이면 남은 채널을 계속 두드리지 않고 **그때까지 끝난 채널만 저장하고 중단**.

## C. 선택 · 다운로드 UX
16. **클릭 = 보기, 체크박스 = 내보내기 선택**(Discord처럼 클릭은 열람). 채널/DM 행(오른쪽 끝), 카테고리(3상태), 서버(3상태: 레일 아이콘 모서리 + 사이드바 제목), DM 전체(검색 필터 적용분) 지원. 선택은 서버를 오가도 유지.
17. **다운로드 버튼 = 분할 버튼**: 본체를 누르면 마지막에 쓴 형식으로 **즉시 시작**(처음 요구사항대로), ▾ 를 누르면 형식·기간·**메시지 개수**·HTML 테마·언어 팝오버. 기본 형식 HTML, 마지막 선택 기억. 날짜 범위나 개수가 잘못되면 시작하지 않고 오류를 보여줌.
18. **우상단 "N개 선택됨" 칩** → 선택 목록 팝오버(개별 해제/전체 해제).
19. **내보내기 범위**: 기본은 채널의 *전체* 기록(화면에 로드된 200개씩이 아님). 기간(시작/끝)과 **메시지 개수(1~100,000, 채널마다 적용)** 로 줄일 수 있고, 규칙은 다음과 같음(처음 요구사항의 2가지 + 설계 중에 정한 나머지):
    - 기간 없음 + N개 → **지금부터 거슬러 올라가 최근 N개**(최신순으로 가져온 뒤 파일에는 오래된 것부터 기록).
    - 시작일 + N개 → **시작일(오래된 쪽)부터 앞으로 N개**. 종료일도 있으면 그 날짜를 넘지 않음.
    - (판단) 종료일만 + N개 → **종료일까지의 최근 N개**. 시작일 > 종료일은 오류.
    - "최근 N개" 모드는 N개를 메모리에 모았다가 쓰기 때문에 상한을 100,000으로 둠(전체가 필요하면 "전체" 사용 — 이쪽은 스트리밍).
    - 파일 머리말에 적용된 범위가 적힘(예: "최근 200개 메시지"). `after` 방향(오래된 것 → 최신)으로 100개씩 가져오며 진행률 계산.
20. **여러 개를 선택하면 ZIP 1개**(폴더: `서버/카테고리/채널.확장자`, DM은 `Direct Messages/이름.확장자`), 1개면 파일 그대로 저장. ZIP 하나는 약 3.75GB / 65,535개 파일이 한계(넘으면 해당 채널은 실패 목록에 표시).
21. **채널/DM별 개별 설정**: 우상단 "N개 선택됨" 목록의 각 행에서 ×(제거) 왼쪽 **톱니바퀴**로 그 채널만 기간·개수를 따로 지정(예: 한 채널만 200개, 나머지는 전체). "공통 설정 사용"을 끄면 현재 공통값을 복사해 시작하고, "공통 설정으로 되돌리기"로 해제. 개별 설정이 있는 행은 요약 문구와 톱니바퀴의 점으로, 선택 칩은 점으로 표시. 개별 설정은 **기간+개수만** 해당하고 형식/HTML 테마/언어는 전체 공통(한 ZIP 안에 형식이 섞이면 혼란스러워서), 저장되지 않으며 선택이 해제되면 함께 사라짐.
22. **진행 패널**: 채널별 상태·가져온 메시지 수, 취소 버튼, 완료 요약(접근 불가로 건너뛴 채널/오류 목록). **취소하면 아무것도 자동 저장되지 않으며**, 이미 끝난 채널이 있으면 "완료된 N개 채널 저장" 버튼으로 직접 저장.
    ZIP을 만드는 중에는 취소할 수 없음(로컬 작업이라 금방 끝남).
23. **세션 만료/저장 실패 시 보호**: 내보내기 도중 401(세션 만료)이 나면 그때까지 끝난 채널을 자동 저장. 자동 저장이 실패하면 보관해 두었다가 "저장" 버튼으로 재시도. 내보내는 중에 탭을 닫거나 새로고침하면 확인창이 뜸.

## D. 내보내기 형식
24. **6개 형식**: HTML, TXT, Markdown, Excel(.xlsx) + 요청에 없던 **CSV, JSON** 추가(데이터 분석/백업용으로 저비용·고가치).
25. **HTML**: 단일 파일, 앱과 같은 DOM/CSS로 Discord 다크 스타일(라이트 선택 가능), 스크립트 없음 + 엄격한 CSP. 아바타/이미지는 Discord CDN 링크.
26. **첨부파일 본문은 다운로드하지 않음**(링크만 기록). Discord CDN 링크는 시간이 지나면 만료될 수 있음 → 미디어 포함 ZIP은 v2 후보.
27. **XLSX**: 라이브러리(SheetJS 등) 대신 직접 구현한 경량 작성기(알려진 취약 버전 회피, 번들 소형화). 모든 셀은 문자열 셀(수식 실행 불가), 시트당 최대 행 수 초과 시 시트 분할, 머리글 고정·열 너비 지정.
    한 채널을 통째로 메모리에 올려 만들기 때문에 수십만~백만 개 메시지 채널은 느리고 메모리를 많이 씀(그럴 땐 CSV/JSON 권장).
28. **CSV**: UTF-8 BOM(엑셀 한글용). 메시지/작성자 ID 같은 18~19자리 숫자는 **엑셀이 숫자로 해석해 `1.42E+18` 로 보이고 저장하면 뒷자리가 깨질 수 있음** — 엑셀에서 열 거면 XLSX를 쓰거나 "데이터 > 텍스트/CSV 가져오기"에서 ID 열을 텍스트로 지정.
29. **타임존/시간 표기**: 브라우저 로컬 타임존, `YYYY-MM-DD HH:mm:ss`. 옵션으로 바꿀 수 있는 구조(UI 노출은 안 함).
30. **파일명/경로**: 윈도우 금지문자/예약어/길이 정리, 중복 시 채널 ID 접미사, 파일과 폴더 이름 충돌 방지. CSV/엑셀 수식 주입(`= + - @`) 무력화.
31. **Markdown 내보내기 안전장치**: 메시지 속 원시 HTML과 헤딩/인용/목록 위조를 이스케이프하고, 라벨이 다른 주소처럼 보이는 링크(`[https://good](https://evil)`)에는 실제 도메인을 덧붙임(HTML 내보내기·앱 화면도 동일).

## E. UI
32. **다크 테마 고정**(Discord 기본). 색/치수는 Discord 다크 테마를 최대한 동일하게. **Discord 로고/자산은 사용하지 않음**(홈 버튼 등은 자체 제작 아이콘) — 상표 문제 회피.
33. **한국어/영어**: 브라우저 언어 자동 감지(한국어 또는 감지 불가 → 한국어, 그 외 언어 → 영어), 옵션 팝오버에서 자동/한국어/English 수동 전환. 내보낸 파일 안의 고정 문구도 같은 언어.
34. **처음부터 제외하기로 한 기능**: 내 프로필/유저 패널, 고정 메시지, 멤버 목록, 검색, 메시지 입력창, 알림·멘션 뱃지, 서버 폴더, 서버 메뉴, 설정, 음성 연결, 이모지/스티커 피커, 스레드 사이드 패널, 역할 색상.
35. **예외로 최소 포함**: ① 연결된 계정 이름(작은 정적 텍스트, 계정 확인용) ② DM 목록 이름 필터(DM이 수백 개일 수 있어서) ③ 채널 주제(헤더 텍스트) ④ 읽기 전용 안내 ⑤ 키보드용 "건너뛰기" 링크.
36. **메시지 표현 범위**: Discord 마크다운(굵게/기울임/밑줄/취소선/스포일러/코드/인용/제목/목록/링크), 멘션(사용자·채널·역할), 커스텀 이모지, 시간 표기(`<t:…>`), 답장, 첨부(이미지·영상·오디오·파일), 임베드, 리액션, 스티커, 시스템 메시지(입장·핀·부스트 등), 투표·전달 메시지는 간단 표현.
37. **긴 채널 성능**: 가상화 대신 `content-visibility: auto`로 오프스크린 렌더 비용 절감(위로 스크롤하며 prepend 하는 구조에서 가상화는 복잡도 대비 이득이 작음).
38. **최소 창 너비 900px**(그보다 좁으면 가로 스크롤). 모바일/좁은 화면 레이아웃은 만들지 않음.

## F. 보안 · 위험 · 검증 범위 (정직하게)
39. **Discord 약관**: 사용자 토큰으로 API를 직접 호출하는 것은 Discord 이용약관/개발자 정책상 허용되지 않는 "셀프봇" 영역에 해당할 수 있습니다(DiscordChatExporter 등 유사 도구와 같은 위험). 읽기(GET) 전용, 순차 요청(Discord의 속도 제한 준수), 공식 클라이언트 위장 없음으로 위험을 낮췄지만 **계정 제재 가능성이 0은 아닙니다.** 개인 계정 백업 용도로만 쓰는 것을 권장합니다.
40. **보안**: 모든 메시지 텍스트는 공격자가 조작 가능한 입력으로 취급 — React에서 `dangerouslySetInnerHTML` 금지, HTML 내보내기는 전부 이스케이프 + URL 스킴 화이트리스트 + CSP, 파서는 입력 크기에 선형.
41. **스토어 게시 시**: 이름에 "Discord"가 들어가면 Chrome 웹 스토어 상표 정책에서 반려될 수 있음(개인용 "압축해제된 확장 로드"에는 영향 없음). 라이선스는 MIT입니다([LICENSE](../LICENSE)).
42. **검증 범위**: 실제 Discord 계정/서버로는 테스트하지 않았습니다(사용자 토큰을 다루지 않기 위해). 대신 ① 모킹된 fetch 단위 테스트 ② 데모 모드 UI ③ **실제 크롬에 빌드된 확장을 로드하고 `discord.com` 을 로컬 가짜 서버로 바꿔서** 토큰 캡처·라이브 부팅·200개 로딩·403 구분·내보내기·CSP 위반 0건까지 end-to-end로 확인했습니다.
